# Demo script (≈5 minutes, narrated, outputs only)

Preparation (off camera): `cp .env.example .env`, `make setup`, `make dev-up`, `make frontend`, open http://localhost:5173. For a live run set `COPILOT_MODE=live`, `COPILOT_APP_ALLOWLIST=shop-demo`, and deploy `demo/shop-demo` once beforehand. For a fully offline run keep `COPILOT_MODE=mock` and drive faults with `tools/mock_liara`.

| Time | Scene | What to show / say |
|---|---|---|
| 0:00–0:20 | Problem & promise | "A developer built a site and knows nothing about deploying. Liara's flow is charge → plan → upload → env → deploy → domain. The copilot does it as a conversation and never changes anything without my approval." Show the UI: chat, timeline, status panel with balance and runway. |
| 0:20–1:50 | Deploy wizard | Type «دیپلوی ./demo/shop-demo». Point at: analysis card (Node, port 3000, env keys, health path), plan options with hourly/monthly cost and *runway*, (if balance is low) the manual-step card "charge in console → Done"), env form (secret masked), the **approval card** (steps, cost delta, reversibility, downtime, rollback). Approve → live stepper (create app, env, liara.json, deploy, verify) → success card with URL → open the URL. Optional 20s: «دامنه shop.example.ir» → DNS records card. |
| 1:50–4:10 | Incident | Switch the demo to a leak: live `FAULT_MODE=leak` via «FAULT_MODE=leak» (approve) + `python tools/loadgen.py --url <app url> --mix leak`; mock: `curl -X POST localhost:8081/__mock/scenario -d '{"app":"shop-demo","scenario":"memory_leak","minutes_ago":4}'`. Show the watcher alert opening an incident on its own, the investigation timeline, the evidence card (memory chart climbing, findings), ranked hypotheses with confidence and "what would change my mind", remediation options (restart = cheap but temporary, resize = +cost, code fix = root cause). Approve **restart** → verification rounds → "symptoms resolved". Then click **FixBrief** → **Run coding agent (demo patch)** → diff card → approve `submit_fix` → redeploy → verified. |
| 4:10–5:00 | Safety & limits | Policy tab: T0–T3 table, guarded tools disabled. Audit tab: propose/approve/execute/verify rows with actors. Limitations tab: manual-step registry. Close: "Real Liara APIs, honest about what they can't do, human in the loop, evidence-first SRE, and a bridge to your coding agent." |

Tips: keep the mouse slow; read the Persian cards aloud; never show source code; keep `tools/loadgen.py` running in a hidden terminal during the incident scene so symptoms appear within ~2 minutes on a live account.
